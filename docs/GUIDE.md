## 1. Как работает сервис

**Сценарий пользователя.**

1. `/start` → бот присылает оферту, политику ПДн и правила файлами `.docx` и кнопку
   «Принимаю условия». Без согласия дальше нельзя. Согласие и его версия сохраняются.
2. Меню: выбор профиля («ГОСТ 7.32-2017», «НИТУ МИСИС»), «Как это работает»,
   «Документы и правила», «Поддержка», «Изменить email» (если включены чеки).
3. Пользователь присылает `.docx` (до 20 МБ). Бот отклоняет `.doc`, `.docm`, повреждённые,
   зашифрованные файлы и документы с непринятыми исправлениями — с понятным объяснением.
4. За 1–2 секунды приходит **бесплатный отчёт**: что найдено (заголовки, таблицы, рисунки,
   источники), сколько нарушений по категориям, сколько мест требуют уточнения, цена.
5. Оплата через СБП (кнопка «Перейти к оплате») или бесплатно в бета-режиме.
6. После оплаты сервис может уточнить у ИИ неуверенные места и задать пользователю до
   5 вопросов кнопками («Это заголовок или обычный текст?»). Нет ответа за 30 минут —
   берётся наиболее вероятный вариант.
7. Пользователь получает `<имя>_ГОСТ.docx` и отчёт: что исправлено, какие оформительские
   правки текста сделаны, что проверить вручную. Кнопки «Всё отлично» / «Что-то не так»
   (жалоба → одна бесплатная повторная обработка).

**Главная гарантия.** Перед выдачей файл проходит две независимые проверки:
- *целостность* — текст результата сравнивается с исходным абзац к абзацу (с учётом
  разрешённых оформительских правок из журнала), плюс число рисунков, таблиц, формул,
  сносок, гиперссылок и номера пунктов списков;
- *линтер* — результат открывается заново, и оформление каждого абзаца сверяется с профилем.

Не прошла хоть одна → файл не выдаётся, деньги возвращаются автоматически, владельцу
приходит уведомление.

**Что меняется в тексте (белый список).** Только: пробелы/табуляции в начале и конце
абзаца, двойные пробелы, пустые абзацы, номер заголовка («1.2.» → «1.2»), точка в конце
заголовка, регистр заголовков структурных элементов («Введение» → «ВВЕДЕНИЕ»), префикс
подписи («Рис. 3.» → «Рисунок 3 –»), набранные вручную маркеры списков, старое оглавление
(заменяется автоматическим). Всё перечисляется в отчёте пользователю.

## 2. Архитектура

```text
Telegram ◄──► bot ──► очередь (Redis) ──► worker ──► PostgreSQL, том files
                                            │
                              ЮKassa API ◄──┘ (проверка платежей и возвратов каждые 30 с)
```

Сервер **сам ходит** в Telegram и ЮKassa, к нему никто не обращается снаружи. Поэтому
не нужны ни домен, ни HTTPS-сертификат, ни открытые порты — подойдёт любой VPS.

| Сервис | Роль |
| --- | --- |
| `bot` | диалог в Telegram (long polling), приём файлов, кнопки. Документы **не** обрабатывает |
| `worker` | анализ и оформление (внутри LibreOffice и шрифты Times New Roman), ИИ, вопросы, выдача, возвраты; фоновые задачи: проверка платежей и возвратов каждые 30 секунд, удаление файлов по срокам раз в 10 минут |
| `migrate` | разовый: применяет миграции БД при запуске и завершается; `bot` и `worker` стартуют после него |
| `postgres` | заказы, платежи, возвраты, вопросы, вызовы ИИ, аудит событий, отзывы |
| `redis` | очередь задач и состояние диалогов бота |

**Конвейер ядра (`app/core`)** — не зависит от бота, БД и оплаты, запускается из CLI:

1. `docx_io` — проверка пакета (zip, размер после распаковки, макросы, исправления),
   безопасный XML, вычисление эффективного форматирования (стили, наследование, нумерация).
2. `parser` — документ → промежуточное представление (IR): блоки с run и ссылками на XML.
3. `classify/rules` — каждому блоку тип и уверенность; `classify/llm` — ИИ для серой зоны;
   `classify/resolve` — объединение правил, ИИ и ответов пользователя.
4. `normalize` — разрешённые правки текста с журналом.
5. `builder` — новый документ в копии исходного пакета (картинки, сноски, формулы
   сохраняют связи), стили профиля, оглавление, разделы, колонтитулы.
6. `render` — LibreOffice: PDF для номеров страниц в оглавлении и визуальной проверки.
7. `integrity`, `linter` — проверки; `report` — отчёты.

**Статусы заказа** (`app/db/order_fsm.py`): `created → analyzing → analyzed` (или `rejected`)
`→ awaiting_payment → paid` (или `expired`/`canceled`, из них можно снова платить)
`→ processing → (awaiting_user_input →) done` или `failed → refunded`;
`done → complaint → done | refunded`. Любой другой переход — ошибка.

**Папки:**

```text
app/config.py           настройки из .env
app/core/               ядро (см. выше), cli.py — команды для разработчика
app/core/profile.py     схема profile.yaml
app/profiles/<id>/      профили: profile.yaml (+ README, template.docx для просмотра)
app/prompts/            системный промпт классификатора ИИ
app/bot/                handlers/, texts.py (все тексты бота), keyboards.py, middlewares.py
app/services/           сценарий заказа, уведомления, юридические файлы, общий контекст
app/payments/           клиент ЮKassa, оплата и возвраты
app/workers/            задачи и расписание arq
app/db/                 модели, переходы статусов, миграции Alembic
docker/                 Dockerfile.app, Dockerfile.worker, *.dockerignore, docker-compose.yml
docs/source/            ТЗ, ГОСТ 7.32-2017, методичка вуза — источники требований
docs/legal/             шаблоны оферты/политики/правил (.md) и готовые файлы (ready/)
tests/                  unit/, integration/, synth.py (генератор документов), corpus/ (не в git)
```

## 3. Запуск

### Сервер

Ubuntu 22.04/24.04, 2 vCPU, 4 ГБ RAM, 20+ ГБ диска. Домен и открытые порты не нужны.

```bash
curl -fsSL https://get.docker.com | sh          # Docker и Compose
git clone <репозиторий> gost-bot && cd gost-bot  # или скопировать папку проекта
cp .env.example .env && nano .env                # см. раздел 4
docker compose up -d --build                     # собрать и запустить
docker compose ps -a                             # bot, worker, postgres, redis — Up; migrate — Exited (0)
```

Проверка: напишите боту `/start` — должны прийти три документа и кнопка согласия.

`docker compose` запускается из корня проекта: в `.env` строка
`COMPOSE_FILE=docker/docker-compose.yml` говорит, где лежит файл. Без `.env` используйте
`docker compose -f docker/docker-compose.yml --env-file .env ...`.

### Полезные команды

```bash
docker compose logs -f worker        # логи (JSON); также bot, migrate
docker compose restart bot           # перезапуск сервиса
docker compose down                  # остановить (данные в томах сохраняются)
docker compose exec postgres psql -U gost gost   # консоль БД
```

### Обновление

```bash
git pull && docker compose build && docker compose up -d
```

Простой — несколько секунд. Оплаты, прошедшие во время перезапуска, найдёт следующая
проверка; задачи в Redis переживают перезапуск worker, диалоги бота хранятся в Redis,
сообщения пользователей Telegram придержит и отдаст после запуска. Миграции БД применяет
`migrate`.

### Резервные копии

Встроенных бэкапов нет. Используйте снапшоты сервера у хостинг-провайдера или
периодический `docker compose exec -T postgres pg_dump -U gost -Fc gost > gost.dump`.
Документы пользователей бэкапить не нужно — они и так удаляются через часы.

## 4. Переменные окружения

Все настройки — в `.env` (шаблон `.env.example`). Комментарии в `.env` пишите только
на отдельных строках: Docker Compose считает текст после значения его частью.

**Общее**

| Переменная | Что это |
| --- | --- |
| `COMPOSE_FILE` | путь к compose-файлу, чтобы `docker compose` работал из корня |
| `ENVIRONMENT` | `dev` / `test` / `prod`. В `prod` сервис откажется стартовать с `DEBUG_TEXT_LOGS=true` |
| `LOG_LEVEL` | подробность логов: `DEBUG`, `INFO`, `WARNING`, `ERROR` |
| `DEBUG_TEXT_LOGS` | разрешить текст документов в логах — только для отладки на своём компьютере |
| `SENTRY_DSN` | адрес Sentry для сбора ошибок; пусто — выключено. Пакет Sentry в образ не входит: добавьте `--extra sentry` к `uv sync` в Dockerfile |

**Telegram**

| Переменная | Что это |
| --- | --- |
| `BOT_TOKEN` | токен бота от @BotFather. Пусто — бот запускается, но Telegram не опрашивает |
| `BOT_USERNAME` | имя бота без `@`: после оплаты пользователь возвращается в `t.me/<имя>` |
| `ADMIN_IDS` | ваши Telegram id через запятую (узнать — у @userinfobot): доступ к `/admin` и уведомления |

**База данных и Redis**

| Переменная | Что это |
| --- | --- |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | учётная запись и имя базы; задаются при **первом** запуске. Пароль обязательно сменить |
| `DATABASE_URL` | адрес БД — нужен только при запуске без Docker (в Docker собирается из `POSTGRES_*`) |
| `REDIS_URL` | адрес Redis — только без Docker |

**ЮKassa**

| Переменная | Что это |
| --- | --- |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | shopId и секретный ключ магазина. Сначала тестового, потом боевого |
| `PRICE_RUB` | цена оформления одного документа, ₽ |
| `PAYMENT_TTL_MINUTES` | сколько живёт ссылка на оплату в боте (сам платёж СБП живёт час — поздняя оплата засчитывается) |
| `RECEIPTS_ENABLED` | отправлять кассовые чеки 54-ФЗ через ЮKassa; бот спросит email |
| `RECEIPT_VAT_CODE` | код НДС в чеке (1 — без НДС). Уточнить у бухгалтера под ваш налоговый режим |

**ИИ (OpenAI)**

| Переменная | Что это |
| --- | --- |
| `LLM_ENABLED` | включить уточнение неуверенных абзацев через ИИ |
| `OPENAI_API_KEY` | ключ API OpenAI; обязателен при `LLM_ENABLED=true` |
| `LLM_MODEL` | основная модель, по умолчанию `gpt-6-luna` |
| `LLM_ESCALATION_MODEL` | модель для повтора, если ответ невалиден, по умолчанию `gpt-6-sol` |
| `LLM_MAX_COST_PER_DOC_USD` | потолок расходов на ИИ на один документ, $ |
| `LLM_MAX_BLOCKS` | максимум абзацев в одном запросе; остальное — вопросы пользователю и отчёт |
| `LLM_TIMEOUT_S` | таймаут запроса к ИИ, секунды |

**Классификация и вопросы**

| Переменная | Что это |
| --- | --- |
| `CLASSIFY_ACCEPT_THRESHOLD` | уверенность (0–1), с которой решение правил принимается без ИИ |
| `CLASSIFY_LLM_THRESHOLD` | ниже этой уверенности блок сразу идёт в вопросы пользователю; между порогами — в ИИ |
| `MAX_USER_QUESTIONS` | максимум вопросов пользователю на документ |
| `QUESTION_TIMEOUT_MINUTES` | сколько ждать ответов, потом — лучший вариант с пометкой в отчёте |

**Бета**

| Переменная | Что это |
| --- | --- |
| `BETA_MODE` | бета-режим при старте (переключается и командой `/admin beta on|off`) |
| `BETA_USER_IDS` | Telegram id бета-тестеров через запятую: в бета-режиме оформляют бесплатно |

**Файлы и лимиты**

| Переменная | Что это |
| --- | --- |
| `STORAGE_DIR` | папка для документов (в Docker — общий том `files`) |
| `STORAGE_ENCRYPTION` | шифровать файлы на диске |
| `STORAGE_FERNET_KEY` | ключ шифрования (команда генерации — в `.env.example`). Потеряете — не прочитаете файлы |
| `MAX_UPLOAD_MB` | максимальный размер файла; 20 МБ — предел Telegram для ботов |
| `MAX_UNZIPPED_MB` | защита от zip-бомбы: размер `.docx` после распаковки |
| `PROCESS_TIMEOUT_S` | предельное время оформления одного документа |
| `RATE_LIMIT_DOCS_PER_HOUR` | документов в час на пользователя |
| `RATE_LIMIT_MSGS_PER_MINUTE` | сообщений в минуту на пользователя (лишние игнорируются) |

**Сроки хранения** (те же цифры подставляются в политику ПДн)

| Переменная | Что это |
| --- | --- |
| `RETENTION_UNPAID_HOURS` | через сколько часов удалить файл неоплаченного анализа |
| `RETENTION_PAID_HOURS` | через сколько часов после выдачи удалить исходник и результат |
| `RETENTION_COMPLAINT_DAYS` | сколько дней хранить файл по жалобе (с согласия) или после ошибки |

**Реквизиты** (подставляются в оферту, политику ПДн и правила)

| Переменная | Что это |
| --- | --- |
| `IP_NAME` | ФИО ИП |
| `INN`, `OGRNIP` | ИНН и ОГРНИП |
| `IP_REGISTRATION` | кем и когда зарегистрирован ИП — обязательная информация для потребителя (ст. 9 ЗоЗПП) |
| `CONTACT_EMAIL` | email для претензий и запросов по персональным данным |
| `SUPPORT_CONTACT` | контакт поддержки (`@username` или ссылка); пусто — используется email |
| `TERMS_VERSION` | версия документов. Увеличьте после правки — бот снова попросит согласие у всех |

## 5. Оплата: ЮKassa

1. В личном кабинете ЮKassa создайте **тестовый магазин**, возьмите его shopId и ключ →
   `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`. HTTP-уведомления (webhook) настраивать
   **не нужно** — сервис ими не пользуется.
2. Пройдите оплату и возврат (`/admin refund <id>`) в тестовом режиме.
3. Переход на боевой магазин — только смена двух ключей в `.env` на боевые и
   `docker compose up -d`.

**Как подтверждается оплата.** Worker каждые 30 секунд запрашивает у API ЮKassa
(`GET /v3/payments/{id}`) все неоплаченные платежи младше 2 часов и сверяет статус, сумму,
валюту и номер заказа. Пользователь может не ждать: кнопка «Я оплатил — проверить»
делает ту же проверку сразу. Переход в «оплачено» выполняется один раз под блокировкой
заказа — повторные проверки ничего не меняют. Задержка подтверждения — до 30 секунд.

**Возвраты.** Автоматически — если оформление не удалось после оплаты. Вручную —
`/admin refund <id>`. Повтор не создаёт двойной возврат (ключ идемпотентности). Статус
возврата тоже проверяется каждые 30 секунд; если ЮKassa отменит возврат, владельцу придёт
уведомление «нужен ручной возврат».

**Если ЮKassa попросит ссылку на оферту** (при подключении магазина): выложите готовый
файл из `docs/legal/ready/` туда, где у него будет публичная ссылка — например, Google Диск
(доступ «всем, у кого есть ссылка») или страница в Telegra.ph.

## 6. ИИ: OpenAI

Включается `LLM_ENABLED=true` + `OPENAI_API_KEY`. Работает только после оплаты и только
для абзацев «серой зоны» (уверенность правил между порогами).

- **Что уходит в OpenAI:** до 60 абзацев, каждый не длиннее 300 символов, их признаки
  (стиль, жирность, выравнивание) и по 80 символов соседних абзацев. Титульный лист — никогда.
  Email, телефоны и ФИО заменяются на `[EMAIL]`, `[PHONE]`, `[NAME]`. Запросы идут с
  `store=false` — OpenAI не сохраняет их у себя.
- **Что возвращается:** только метки (тип, уровень, уверенность) строго по JSON-схеме.
  Неизвестные id и типы отбрасываются, текст в ответе не используется.
- **Модели и цены:** `gpt-6-luna` ($0,10 вход / $0,50 выход за 1M токенов); если ответ
  невалиден или модель отказала — один повтор на `gpt-6-sol` ($2 / $10). Оценка по корпусу —
  около $0,0004 на документ, лимит — `LLM_MAX_COST_PER_DOC_USD`. Расходы каждого вызова
  пишутся в таблицу `llm_calls` и видны в `/admin`.
- **Если ИИ недоступен** — обработка не падает: неуверенное уходит в вопросы пользователю
  и в отчёт, владельцу приходит уведомление.
- **Промпт:** `app/prompts/classifier_system.md`. Модели и цены — `app/core/classify/llm.py`.
- **Проверить точность и стоимость:** `uv run python -m app.core.cli llm-eval`
  (с `--dry-run` — только оценка стоимости, без вызовов).

## 7. Юридические документы

- Шаблоны: `docs/legal/offer.md`, `privacy.md`, `terms.md`. В них плейсхолдеры `{{IP_NAME}}`,
  `{{INN}}`, `{{OGRNIP}}`, `{{IP_REGISTRATION}}`, `{{EMAIL}}`, `{{SUPPORT}}`, `{{PRICE}}`,
  сроки хранения, версия — значения берутся из `.env`.
- **В боте** документы приходят файлами `.docx`: при первом `/start` (вместе с кнопкой
  согласия) и по кнопке «Документы и правила».
- Публичная ссылка на оферту (если её попросит ЮKassa) — см. конец раздела 5.
- **Готовые файлы с вашими реквизитами:** `docs/legal/ready/`. Пересобрать после правки:
  `uv run python -m app.core.cli legal-docs` (берёт реквизиты из `.env`).
- Все три документа — **черновики**, в начале стоит пометка «Черновик. Перед запуском

  пересоберите `legal-docs`.

## 8. Профили оформления

Профиль — папка `app/profiles/<id>/` с `profile.yaml`. Новый вуз добавляется без кода.
Схема строгая (`app/core/profile.py`): опечатка в ключе или недопустимое значение — профиль
не загрузится. У каждого значения в YAML комментарий-источник: `[ГОСТ п.]`, `[ВУЗ]`,
`[SPEC]` или `[?]` (допущение).

**Профили сейчас:** `gost_7_32_2017` («ГОСТ 7.32-2017») и `misis` («НИТУ МИСИС», по
методичке кафедры БИСУП, где она молчит — по ГОСТ). Источники — `docs/source/`.

**Ваши решения по профилям (этап 0):**
- кегль в профиле ГОСТ — 12 пт; в вузовском — 12 пт по методичке;
- тире в подписях: ГОСТ — «—», вуз — «–» («Рисунок 3 – Название»);
- синонимы заголовков («Список литературы», «ПРИЛОЖЕНИЕ 1») не переименовываются — только
  сообщение в отчёте;
- оглавление создаётся, если было в исходнике или документ длиннее 10 страниц и в нём не
  меньше 2 заголовков;
- вуз: после заголовков структурных элементов — 24 пт; подпись рисунка — 1,5 интервала;
  строка с номерами столбцов проверяется у каждой таблицы (только предупреждение);
- набранные вручную маркеры списков заменяются на маркеры профиля.

**Добавить вуз:**
1. Скопируйте `app/profiles/misis` в `app/profiles/<код>`; в `profile.yaml` `id` = имя папки,
   `title` — текст кнопки (до 40 символов).
2. Перенесите требования методички; методичку положите в `docs/source/`.
3. `uv run pytest tests/unit/test_profiles.py` — схема валидна.
4. Посмотреть стили в Word: `uv run python -m app.core.cli build-template <код>` →
   `app/profiles/<код>/template.docx` (только для просмотра — сервис строит стили из YAML сам).
5. Прогон по корпусу (раздел 13) — «N/N без ошибок».
6. `docker compose up -d --build` — кнопка появится в меню.

## 10. Файлы и персональные данные

- Документы хранятся под случайными именами (UUID), без исходных имён; можно шифровать
  (`STORAGE_ENCRYPTION`).
- Удаление по срокам — раз в 10 минут: неоплаченное через 2 часа, выданное через 24 часа,
  по жалобе или после ошибки — через 14 дней. Каждое удаление пишется в аудит (`events`).
- В логах нет текста документов: только номера заказов, id блоков, коды ошибок.
- Защиты: проверка содержимого файла (а не расширения), лимит распаковки, безопасный
  разбор XML, отказ при макросах, удаление ссылок на внешние шаблоны, LibreOffice — с
  отдельным профилем и таймаутом, лимиты сообщений и документов, бан.

## 11. Тесты

```bash
uv sync                                            # зависимости, включая dev
uv run pytest                                      # unit; интеграционные пропускаются
```

**Unit-тесты** (`tests/unit/`, ~125 штук, секунда) — без внешних сервисов:
- `test_docx_io` — отказ для битых/старых/зашифрованных файлов, макросов, исправлений,
  zip-бомб; наследование стилей; нумерация Word;
- `test_classify` — по тесту на каждое правило классификации;
- `test_normalize` — по тесту на каждую разрешённую правку текста;
- `test_build` — сборка «кривого» документа по обоим профилям, перенос рисунков, формул,
  сносок, гиперссылок, альбомных страниц; проверка целостности ловит подменённое слово и
  потерянный рисунок; линтер ловит прямое форматирование, поля, точку в заголовке;
- `test_llm` — ИИ на подменённом клиенте OpenAI: маскирование, титульный лист не уходит,
  чужие id отбрасываются, эскалация, бюджет, отказ модели;
- `test_profiles`, `test_config`, `test_order_fsm`, `test_models`, `test_legal_docs`.

Документы для тестов строит `tests/synth.py` из сырого XML — в том числе «кривой»
документ со всеми типичными ошибками студентов.

**Интеграционные тесты** (`tests/integration/`) — на настоящих PostgreSQL и Redis:
- `test_payments` — успешная оплата и повторная проверка, фоновая проверка, отмена, поздняя
  оплата, поддельные данные (несуществующий платёж, неверная сумма), возврат без дублей,
  проверка статуса возврата; API ЮKassa подменён (`fakes.py`);
- `test_flow` — полный путь заказа: анализ → оплата → вопросы → ответы → результат,
  битый файл, повтор без оплаты, удаление файлов по срокам;
- `test_bot` — бот с подменённым Telegram: документы файлами, согласие, профиль,
  загрузка, очередь; админка; лимиты;
- `test_db` — миграции, переходы статусов под блокировкой (две одновременные проверки
  оплаты засчитывают её один раз).

Запуск интеграционных:

```bash
docker run -d --rm --name t-pg -e POSTGRES_USER=gost -e POSTGRES_PASSWORD=gost \
  -e POSTGRES_DB=gost -p 55432:5432 postgres:16-alpine
docker run -d --rm --name t-redis -p 56379:6379 redis:7-alpine
TEST_DATABASE_URL=postgresql+asyncpg://gost:gost@localhost:55432/gost \
TEST_REDIS_URL=redis://localhost:56379/0 uv run pytest
docker stop t-pg t-redis
```

Без `TEST_DATABASE_URL`/`TEST_REDIS_URL` интеграционные тесты пропускаются (`s` в выводе).
Тесты очищают тестовую БД (миграции вниз и вверх) — **не указывайте боевую базу**.

Статические проверки: `uv run ruff check .` (стиль и ошибки), `uv run ruff format --check .`
(форматирование), `uv run mypy app tests` (типы, строгий режим).

## 12. CI

`.github/workflows/ci.yml` — GitHub Actions: при каждом `push` и pull request GitHub на своём
сервере поднимает PostgreSQL и Redis, ставит зависимости (`uv sync --frozen` — строго по
`uv.lock`) и выполняет ruff, проверку форматирования, mypy и все тесты, включая
интеграционные. Красный крестик у коммита — что-то сломано, смотреть лог во вкладке
Actions. Зачем: изменение, которое ломает оформление, оплату или типы, видно до того, как
оно попадёт на сервер. Работает, когда проект лежит в GitHub-репозитории. Корпус
реальных работ в CI не прогоняется — он с персональными данными и не хранится в git.

## 13. Корпус и качество оформления

Корпус — реальные работы в `tests/corpus/raw/` (в git не попадает). Команды CLI:

```bash
uv run python -m app.core.cli analyze --profile misis file.docx   # отчёт до оплаты
uv run python -m app.core.cli dump file.docx                      # тип и уверенность каждого блока
uv run python -m app.core.cli format --profile misis --out out tests/corpus/raw/*.docx
uv run python -m app.core.cli compare src.docx out/src_ГОСТ.docx  # PDF «до | после» (нужен LibreOffice)
uv run python -m app.core.cli annotate                            # черновая разметка + review.csv
uv run python -m app.core.cli annotate --apply tests/corpus/review.csv
uv run python -m app.core.cli eval                                # точность классификации
uv run python -m app.core.cli llm-eval [--dry-run]                # ИИ на серой зоне
uv run python -m app.core.cli build-template <профиль|all>
uv run python -m app.core.cli legal-docs                          # docs/legal/ready/*.docx
```

С LibreOffice (номера страниц в оглавлении, `compare`) запускайте в контейнере worker:

```bash
docker compose run --rm -v "$PWD":/srv/work -w /srv/work worker \
  python -m app.core.cli format --profile misis --out out tests/corpus/raw/*.docx
```

**Результаты на корпусе (19 работ МИСИС):** целостность 19/19, ошибок линтера 0 — по
обоим профилям; отчёт до оплаты — до 0,75 с; оформление — до 11 с (138 страниц);
оглавление — номера страниц найдены для 81/81 записи. Точность классификации ещё не
посчитана: нужна ваша проверка разметки.

**Как проверить разметку:** откройте `tests/corpus/review.csv` в Excel (разделитель «;»).
В строках, где тип неверный, заполните `correct_type` (и `correct_level` для заголовков),
в проверенных файлах поставьте «да» в `checked`. Затем `annotate --apply` и `eval`.
Каждая жалоба из беты — новый файл в корпус и повод поправить правила.

## 15. Принятые решения и ограничения

**Решения:**
- Уверенность классификации = доминирование лучшего варианта над вторым × сила голоса.
- В коротких работах (до 15 страниц) без нумерованных разделов заголовки без номера
  («Цель работы», «Вывод») оформляются как подзаголовки — иначе каждый начинался бы с новой
  страницы. Отмечается в отчёте.
- Лист задания сразу после титульного листа переносится как есть, вместе с титульным.
- Титульный лист не меняется: его форматирование «запекается», поля — по профилю, номер
  страницы на нём не показывается, но считается.
- Разрывы разделов схлопываются (кроме смены ориентации) — это лечит документы,
  конвертированные из PDF. Разрывы страниц перед заголовками с новой страницы удаляются.
- Таблицы: структура и границы сохраняются, текст — стиль профиля, шапка — по профилю.
- Нумерация рисунков и таблиц не меняется — при пропусках и дублях сломались бы ссылки
  в тексте; проблема уходит в отчёт.
- Автонумерация Word у заголовков переносится в текст («1.2 Название»).
- Колонтитулы заменяются номером страницы.
- Без веб-сервера: оплата подтверждается опросом API ЮKassa (до 30 секунд задержки)
  вместо webhook, юридические документы — файлами в боте вместо страниц `/legal`. Это
  отступление от ТЗ ради простоты: не нужны домен, HTTPS и открытые порты.
- Оглавление — поле Word с готовыми строками и номерами страниц из LibreOffice; при открытии
  Word предложит обновить поля (может отличаться на ±1 страницу).
- К набору стилей из ТЗ добавлены вспомогательные (заголовок оглавления, название
  приложения, шапка таблицы, варианты заголовков для интервалов «между заголовками подряд»).

**Ограничения:**
- Документы после конвертации из PDF: строки, разбитые на абзацы, и слова через табуляции
  не исправляются (это изменение текста) — пользователь получает предупреждение.
- Текст внутри надписей (text boxes) не форматируется по профилю — переносится как есть.
- Совместимость с Word проверена косвенно (LibreOffice, строгий порядок XML). Откройте
  несколько результатов в Word перед запуском.

## 17. Неполадки

| Симптом | Что проверить |
| --- | --- |
| Бот молчит | `docker compose logs bot`: «BOT_TOKEN is not set» — нет токена; не вы ли в бане; лимит 30 сообщений в минуту |
| «Анализирую документ…» и тишина | `docker compose logs worker`; worker запущен? `docker compose ps` |
| Оплата прошла, документа нет | подождать 30 секунд или кнопка «Я оплатил — проверить»; `/admin problems`; логи worker; ключи ЮKassa в `.env` (тестовые vs боевые) |
| bot/worker не стартуют | `docker compose logs migrate` — миграции не применились (часто неверный `POSTGRES_PASSWORD` после первого запуска) |
| «Не удалось оформить» | `/admin problems` — код ошибки; исходник хранится 14 дней; прогоните файл через `cli format` локально |
| ИИ не работает | `LLM_ENABLED`, `OPENAI_API_KEY`; в `events` — запись `llm_unavailable`; сервис работает и без ИИ |
| Кончается место | уведомление владельцу; `docker system prune` (старые образы), сроки хранения |
